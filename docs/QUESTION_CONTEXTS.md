# 問題文の状況と問いの具体化

2026年10月20日追加。通常教材の思考問題812問に、解答を開く前に読める「状況・前提」を付けました。

原則だけを提示して理由を尋ねていた292問は、構成と現象を示した具体的な問いへ変更しました。質問のあったQ055・Q141・Q218・Q245・Q253など11問は、個別の比較対象や回答範囲も見直しています。重複を除き、問いを変更したのは301問です。

## 書き方

- 誰がどの装置へ接続し、何を実現したいかを示す。
- 変更済みの設定と、まだ変えていない設定を分ける。
- 宛先IP・MAC・経路プレフィックス、内側・外側、制御情報・実データなど、比較対象を明記する。
- 答えを導くのに必要な条件は問題側へ書き、仕組みの説明や結論は解説側へ置く。
- 一般的な状況は同じ知識のカードで共有し、特定の数値・構成が必要な問題は個別に記述する。

例えばQ253は、二拠点ルータがGRE over IPsecの終端であり、その仮想回線上でIPv4のOSPFを使うと示しました。「内側」は元のOSPFパケットのIPヘッダー、「外側」は対向終端へ配送するIPヘッダーと定義し、OSPFが広告するLANのプレフィックスを比較する問題と混同しないようにしています。OSPFの宛先の解答は状況欄へ先に書きません。

用語の名前・意味を問う140枚と、既に独自の条件を持つ予想78問には今回の共通状況を付けません。短い解答、短い解説、詳しい解説、出典・頻度、番号・保存IDは維持します。教材原本 `data/source/` は変更しません。

## 編集と検証

追加教材は `data/editorial/question_contexts.json`。著作元は `scripts/contexts/atoms-1.mjs`〜`atoms-4.mjs` の366知識と、`questions.mjs` の個別編集です。

知識別の行は `ID接尾辞|状況・前提|抽象的な原則問題に代わる問い`。個別編集は `context`（任意）、`question`、`answerFocus` だけを持ち、解答の変更には使えません。

再生成は `node scripts/author-question-contexts.mjs`。`node scripts/validate.mjs`、`node --test`、`node scripts/build.mjs`（または `npm run check`）で検証します。テストでは、全件対応、抽象形式の残存、質問された問題の条件、著作元との一致、既存解答・番号の保持、HTMLのエスケープを確認します。
