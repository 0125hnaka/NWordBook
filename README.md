# NWordBook

ネットワークスペシャリスト試験の午後対策を、スマートフォンで短問反復するWebアプリです。問題を見て頭の中で答え、解答・解説・思考トリガーを確認します。

公開アプリ：[NWordBook](https://0125hnaka.github.io/NWordBook/)。スマートフォンのブラウザーから利用できます。

公開リポジトリ：[0125hnaka/NWordBook](https://github.com/0125hnaka/NWordBook)。2026年10月17日にユーザーの承認を受けて公開しました。通常のpushで自動検証されます。今後の変更依頼は、検証・push・Actionsの確認・公開サイトへの反映まで継続して承認されています。

このフォルダーは単独で動くプロジェクトです。隣の `nw-afternoon-flashcards` は引継ぎ資料として保持しており、実行時には参照しません。

## 起動する

Node.js 22.12以降（推奨24）が必要です。外部パッケージのインストールは不要です。

このフォルダーをターミナルで開き、実行します。

```sh
node scripts/serve.mjs
```

表示された **http://127.0.0.1:4173/** をブラウザーで開いてください。終了はターミナルで `Ctrl+C`。Windowsでは `start.cmd` からも起動できます。

このPCのCodex内蔵Node.jsも利用できます。`node` が見つからない場合、PowerShellでは次の方法があります。

```powershell
& "$env:USERPROFILE/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe" scripts/serve.mjs
```

`index.html` のダブルクリック（file://）では教材を取得できません。必ずHTTPサーバー経由で開きます。サーバーはこのPCの127.0.0.1だけに接続を許可します。スマートフォンから使う際は、後述のGitHub Pages等へ配置します。

ソースを編集した後は、別ターミナルで `node scripts/build.mjs` を実行し、ブラウザーを再読込みしてください。開発サーバーの起動時にも自動でビルドします。

## 実装した機能

- 紹介エリアを省き、開始画面から直接学習設定を操作
- 通常の開始ボタン下の「予想問題を解く」から、追加調査資料の短問72問・複合演習6問を別枠で学習（通常出題には混在しない）
- 有効分野の全分野ランダム／分野指定、5・10・20問・すべて（既定10問）
- 「すべて」は現在の学び方・分野・復習・非表示設定に合う全カードを重複なく出題。設定の保存・バックアップにも対応
- 学び方は「用語を覚える」「仕組み・判断」「両方を学ぶ」から選択。初期値は用語学習
- 用語カードは「用語→意味・役割」「説明→用語名」の両方向に対応
- 優先度Aの100知識を対象にする「まず覚える100」
- 候補数、候補不足時の実際の問題数、0問時の開始禁止と設定への案内
- 問題→解答・解説・思考トリガー→次の問題→結果
- 学習中は「前の問題」や問題番号で過去の問題を見直し、元の学習中の問題へ復帰。理解度・進捗・元の解答表示と解説の開閉を保持
- 解答後の「わかった／わからない／知らない」の自己申告、保存、結果の内訳
- 「わからない」「知らない」だけを復習する絞り込み
- 問題IDごとの非表示と個別復活、分野・問題数・未確認設定の保存
- 複数の出典、本文のPDFページ、未確認状態、注記、公式問題／解答例／採点講評へのリンク
- 設定・非表示状態のJSONエクスポート／インポート（2MBまで、適用前に内容確認）
- 保存破損・容量超過・保存拒否時の一時保存と日本語通知
- スマートフォン・PC対応、44px以上の主要操作、キーボード操作

問題は独自編集であり、IPA公式・監修教材ではありません。自動採点は行いません。結果は「次へ進んだ数」と「非表示にした数」を別々に表示します。

原本は852問（出典確認済み836問、未確認補充16問）を保持しています。別管理の編集教材として50用語を意味・名前の2方向にした100枚を追加し、全952枚になりました。初期分野・非表示なしでは、用語モード139枚、両方モード759枚です。原本だけを対象とした旧初期候補659問の検証も維持しています。未確認補充と追加分野は既定OFFです。実際の候補数はデータと設定から算出します。

## 理解度の記録と復習

予想問題は通常学習の後の追加演習です。資料ではIPA出題対応は未調査で、未出題を確認した問題という意味ではありません。5・10・20問・全件、苦手復習、非表示と復活、前の問題への移動に対応します。通常の問題数設定とは別に保存します。取り込み元と扱いは [docs/PREDICTIONS.md](docs/PREDICTIONS.md) を参照してください。

学習用語はIPAの試験資料で確認した表記を優先します。「サプリカント」「オーセンティケータ」をはじめ、問題・正答・解説・注意点まで統一しています。根拠と識別子をそのまま残す方針は [docs/IPA_TERMINOLOGY.md](docs/IPA_TERMINOLOGY.md) を参照してください。

答えを見ると、解答のすぐ下に3つのボタンが表示されます。

| 選択 | 意味 |
| --- | --- |
| わかった | 意味・理由を説明できる |
| わからない | 解説を見ても理解できない |
| 知らない | 初めて知った、または覚えていない |

選択後も同じカードに留まるので、解説を読み直し、選び直してから「次の問題へ」を押せます。未選択でも次へ進めます。最新の理解度と記録日時を問題ID単位で保存し、エクスポートにも含めます。自動採点や正答率とは別の自己申告です。

開始画面の「わからない・知らないだけを復習」で絞り込めます。終了画面からも復習できます。分野・向き・推奨100・非表示・未確認設定はすべて維持されます。同じ知識の別カードには理解度を自動転記しません。復習で「わかった」に変更すると、次回の復習候補から外れます。理解度を付けた後で非表示にしたカードは、結果画面の理解度集計から除外し、非表示として集計します。

## 問い方の改善と追加用語

`data/editorial/learning_content.json` に編集内容を分離しています。研究原本のバイト列・ハッシュは変更していません。

- 40問の問い方を個別に具体化し、必要なものは解答も質問と整合するように補足しました。
- 全カードに「答えること」を表示し、用語名・意味・処理の理由・変更する設定などの回答対象を示します。
- 旧「次の原則が成り立つ仕組みを説明せよ」の共通表現は、確認する動作・条件と回答指示を分けて表示します。個別の全文見直しが済んだのは上記40問で、全852問の個別再編集を完了したわけではありません。
- 50用語の意味・名前カード100枚は、既存知識にひも付けた独自編集です。元の知識の出典を表示しますが、追加カード自体のIPA出題を確認した扱いにはしません。
- 用語カードでは詳細解説を折り畳み、短い解答を読みやすくしています。

## 非表示と復活

学習カードの「この問題を非表示」を押すと、現在問から次へ進み、その問題は次回からも除外します。同じ知識を扱う別のカードは残ります。「非表示の問題」画面の「復活する」で戻せます。復活しても、その分野がOFFだったり、未確認補充がOFFだったりすれば通常出題には混ざりません。

学習中に戻る・他の画面へ移る・再読込みする操作では、途中のセッションは終了します。非表示と設定は保存されます。セッションの再開は未実装です。学習画面内の問題移動ではセッションは終了せず、到達済みの問題だけを選べます。過去の問題へ戻ると答えを隠して再考できます。見直し後の「元の○問目に戻る」で復帰し、見直しを完了件数に重複加算しません。見直した問題の理解度は最新の選択で更新します。

## 保存とバックアップ

localStorageの `nw-afternoon:user-state:v1` に保存します。保存先は端末・ブラウザー・配信元（プロトコル、ホスト、ポート）ごとに異なります。ブラウザーのデータ削除やプライベートモードでは失われる場合があります。設定からJSONを書き出してバックアップしてください。

インポート時は型・サイズ・形式を検査し、件数と競合方針を表示します。分野と問題数は読込み内容に置き換え、問題状態は同じ問題IDだけ読込み内容を優先します。他のIDの状態は保持します。未確認補充は、インポート確認画面で再度選択した場合だけONになります。

破損した保存データは自動で上書きしません。その場合は一時保存になり、インポートした状態もその画面内だけで有効です。まずエクスポートし、必要ならブラウザーのサイトデータを手動で整理してから読み込み直してください。

教材更新で見つからなくなった問題IDや分野IDは、将来の再登場に備えて保持します。保存形式の版と教材の版は別に管理します。

## 検証・ビルド

```sh
node scripts/validate.mjs
node --test
node scripts/build.mjs
```

npmを利用できる環境では `npm ci`、`npm run check` でも同じ検証ができます。依存パッケージは0件です。GitHub Actionsはこの方法を使います。

ビルドは原本の件数・ハッシュ・参照整合を検証し、静的配信用の `dist/` を作ります。配信するのは `dist/` の中だけです。全監査JSONや研究CSV、README、テストは配信しません。相対URLで参照するため `https://ユーザー名.github.io/リポジトリ名/` に対応します。

教材原本は `.gitattributes` で改行の自動変換を無効にしています。WindowsとLinuxの間でもファイルのバイト列とSHA-256を保持するため、この設定を維持してください。

実行済みの結果と制限は [docs/VERIFICATION.md](docs/VERIFICATION.md) に記録しています。

## GitHub ActionsとGitHub Pages

**この `nwordbook-app` フォルダーの中身を、GitHubリポジトリのルートに置いてください。** `.github` の隠しフォルダーも含めます。親の `NWordBook` をそのままリポジトリのルートにすると、同梱ワークフローは自動認識されません。その構成を使う場合は `.github/workflows` を親へ移し、working-directory・キャッシュのロックファイル・artifactのパスを調整する必要があります。

2026年10月17日以降、変更依頼は検証・push・Actionsの確認・既存サイトへの更新公開まで継続承認されています。pushで自動検証した後、以下のPagesワークフローを実行します。

1. このプロジェクトをGitHubリポジトリの `main` ブランチへpushします。
2. GitHubリポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
3. **Actions → Deploy to GitHub Pages → Run workflow** で `main` を選択し、公開承認済みの確認項目をチェックして実行します。通常のpushでは公開されません。更新時も変更依頼の継続承認に基づいて手動実行します。
4. deployジョブの公開URLをスマートフォンで開きます。

`ci.yml` はpush・Pull Requestで教材検証、45件のドメイン／保存／教材編集／用語表記／予想問題テスト、ビルドを行います。`pages.yml` は手動実行かつ公開確認がtrueで、mainブランチの場合だけ検証・配信します。Pull Requestでは公開しません。トークン等の追加Secretは不要です。リポジトリ側でPagesの使用やActions権限が許可されている必要があります。

2026年10月17日にリポジトリを公開へ変更し、GitHub Pagesで初回公開しました。[公開処理の実行結果](https://github.com/0125hnaka/NWordBook/actions/runs/39026320934)は成功しています。GitHub Actionsの設定は [GitHub公式ドキュメント](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) に基づいています。

## 問題追加・教材更新

研究原本は保持しています。追加用語と修正文はdata/editorialで別管理しています。原本を更新する場合は、根拠を確認した教材版を用意してから行います。

1. `data/source` の問題・知識・分類・推奨100を更新します。問題の `knowledgeAtomId` は知識の `id` を参照します。
2. 新しい知識は `config/learning_profiles.json` の一つの主分野へ必ず割り当てます。未知の分野を自動で有効にはしません。
3. 知識を取り替える場合はIDを再利用しません。同じIDの非表示状態は維持されます。
4. 未確認の出典を推測で補完せず、確認状態・注記・複数の出典を保持します。
5. 内容を確認後、`dataset_manifest.json` の版、件数、原本4ファイルのSHA-256を更新します。ハッシュは `Get-FileHash -Algorithm SHA256` 等で求められます。
6. 検証・テスト・ビルドを実行します。教材数が意図的に変わった場合は、テストの基準値も理由を記録して更新します。
7. `main` へpushすると自動検証されます。新しい教材の外部配信は、公開承認後にPagesワークフローを手動実行します。`dist` を直接編集しません。

問題数の増加だけを目的に、水増しや出典の捏造をしないでください。原本の出典注記・旧方式の適用条件も保持します。
